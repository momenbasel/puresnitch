Know the filtering scope

The current release does not block individual apps or pause their network connections. Per-process Network Extension filtering is not included. Only the Default profile is enforced; other profiles are organizational labels.

Get started

Install. Approve. Observe.

One universal app for Apple Silicon and Intel Macs running macOS 13 Ventura or later.

Download the app

The signed, Apple-notarized disk image is available on GitHub Releases.

Download for macOS ↗
  1. Move to Applications. Open the DMG and drag PureSnitch into /Applications before launching it.
  2. Approve the helper. Follow the app’s banner to System Settings, General, Login Items & Extensions, then Allow in the Background.
  3. Open Network Monitor. Traffic appears once the helper is approved. Enforcement is a separate, opt-in setting.

Use Homebrew

brew tap momenbasel/puresnitch
brew trust --tap momenbasel/puresnitch
brew install --cask puresnitch

Homebrew requires the one-time tap trust step. The cask installs the signed release.

Already installed? Update with
brew upgrade --cask puresnitch

Build from source ↗

Unsigned builds open the interface only. Helper-backed monitoring requires the signed release or your own Developer ID signing.

Before you get started.

Permissions, privacy, and the limits of the current release.

Does PureSnitch send my network activity anywhere?

The app has no telemetry, analytics SDK, or crash reporter. It fetches enabled blocklists at helper startup and on request. DNS requests go to a DoH upstream only when a client is manually configured to use the experimental proxy. There are no live IP-geolocation requests.

Why does it need a background helper?

The privileged helper reads connection activity and manages optional packet-filter rules. macOS must approve it before traffic monitoring works. Install the app in /Applications, then follow the approval banner in the app. No relaunch is needed after approval.

Can I block one app without affecting another?

No. The shipping build’s packet-filter rules are host-wide and IPv4-only. Per-process filtering requires a Network Extension build that is not distributed. DNS-proxy rules cover only requests explicitly sent to that proxy, and passive app connections are not paused for decisions.

Does it replace my system DNS or VPN?

No. The experimental DNS proxy listens on loopback and needs manually configured clients. It does not change macOS’s system resolver. Host-wide firewall rules can interact with VPN routing or other firewall rules, so check your rules with the VPN enabled.

What if I’m upgrading from v0.1.0 or v0.2.0?

Open the app and resolve the legacy firewall prompt. Decide Later preserves legacy rules unchanged. Keep On replaces them with the current supported rule set and is unavailable when that store is empty. Turn Off deliberately removes them. Read the migration details before choosing.

How do I uninstall it cleanly?

Turn Enforcement Off and choose Remove Helper in the app first. Then remove the app or run brew uninstall --cask puresnitch. Version 0.2.2 also includes cleanup safeguards for removal without that step. The root-owned rule database remains on disk; see the release notes for legacy-state details.
